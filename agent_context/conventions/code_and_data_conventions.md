# Code and Data Conventions

## Current State
The base ETL in `src/main.py` implements most ingestion conventions. Remaining gaps are mainly around packaging, CLI, inference, and tests.

### What the code currently does
- Reads all `*.json` files from `data/raw/evaluation/` via `process_folder()`.
- Iterates over `train` and `test` splits and `input` / `output` roles.
- Validates grids (null, empty, non-2D, inconsistent dimensions, ARC color range 0–9).
- Treats missing `output` in `test` as valid; missing `output` in `train` is an error.
- Transforms each valid grid into a long-format row with metadata (`grid_2d`, `grid_flat`, `grid_hash`, `n_colors`, `color_counts`).
- Enforces `TASKS_PARQUET_SCHEMA` before writing valid rows.
- Writes Hive-partitioned Parquet (`split` → `task_id`) with `pandas.to_parquet(..., engine="pyarrow", partition_cols=...)`.
- Logs validation failures to `logs/quality_<timestamp>.log` and `data/parquet/evaluation_errors/`.
- Stores `source_path` as a repo-relative POSIX path for cross-platform portability.
- Sets `ingested_at` from the source JSON file's mtime for bit-reproducible output.

### Implemented since July 2026 (evaluation MVP slice)
- Inference runner (`src/run_inference.py`) with provider abstraction (`src/providers.py`: mock/openai/ollama).
- Frozen inference results schema in `src/contracts.py`, enforced before every write.
- Response parsing (`src/grid_parser.py`), scoring (`src/evaluator.py`), failure taxonomy v1 (`src/failure_taxonomy.py`).
- Analytics tables + report generation (`src/build_analytics.py` → `data/parquet/analytics/`, `reports/mvp_report.md`).
- Data bootstrap script (`scripts/fetch_arc_data.py`, offline `--sample` mode).

### Current limitations
- Flat `src/` modules (no package initializers); scripts import siblings and run from the repository root.
- Error Parquet schema is not guarded by the frozen schema constant.
- No automated test suite yet (sample-task fixtures exist under `tests/fixtures/sample_tasks/`).
- No orchestration layer (runs are manual CLI invocations).

## Code Conventions
- Keep pipeline code inside `src/` until a package layout is formally adopted.
- Prefer small modules over a single large script once the project starts to grow.
- Keep CLI code thin and delegate work to importable functions.
- Use explicit names for model, task, run, and artifact identifiers.
- Prefer deterministic logic and avoid hidden global state.
- Record technical decisions in `src/DECISIONS.md` when they affect schema, storage, or reproducibility.

## Data Conventions
- Treat ARC task JSON as raw input, not as an analysis-ready format.
- Store raw tasks under `data/raw/evaluation/` (gitignored).
- Write normalized tasks to `data/parquet/evaluation/` (gitignored).
- Write validation errors to `data/parquet/evaluation_errors/` (gitignored).
- Use `artifacts/` for outputs generated by experiments, runs, and analysis (not yet in use).

## Parquet Conventions
- Parquet is the canonical output format for normalized tables and inference results.
- The tasks Parquet schema is frozen as of 2026-06-29; see `TASKS_PARQUET_SCHEMA` in `src/main.py` and `agent_context/conventions/schema_contracts.md`.
- Partition by `split` first, then `task_id` (see `src/DECISIONS.md`, Decision 4).
- Store grids as JSON strings (`grid_2d`, `grid_flat`), not native Parquet nested lists.
- Record `source_path`, `pipeline_version`, and `ingested_at` on every row for traceability.

## Prompt Conventions
- Store prompt templates separately from prompt versions and eval sets.
- Version prompts rather than overwriting them in place.
- Include the model or task context required to reproduce a prompt run.
- Keep prompts readable by both humans and CLI agents.
- See `notebooks/inference_input_reader.py` for loading normalized tasks into prompt-ready structures.

## Observability Conventions
- Grid validation failures: `arc.quality` logger → `logs/quality_<timestamp>.log` (human inspection).
- Grid validation failures: error Parquet → `data/parquet/evaluation_errors/` (programmatic analysis).
- Pipeline operational logs (INFO): console via root logger.
- Inference observability: `latency_ms`, `cost_estimate_usd`, `status`, `error_message`, and timestamps captured on every inference row; per-task INFO logs during runs.

## Reproducibility Conventions
- `ingested_at` is derived from source file mtime, not wall-clock ETL time.
- `source_path` uses POSIX forward slashes regardless of host OS.
- Dependencies listed in root `requirements.txt` (`pandas`, `numpy`, `pyarrow`, `duckdb`).
- Make configuration explicit through files in `configs/` or environment variables documented in `.env.example` (configs not yet in use).

## Assumptions
- `src/main.py` is the current canonical ETL entrypoint until a CLI package is introduced.
- The project will eventually replace direct script execution with importable modules and a CLI.
- `data/` and `logs/` are local working areas, not source-of-truth code.
